# EB synthetic operator acceptance kit

Eight complete, fictional Contract A 2.0 inputs exercise the narrow installed EB V1 workflow. This is engineering acceptance/development, not a representative workload, scientific benchmark, authoring qualification or replacement for EB #121, #123 or #124.

All names, procedures, studies, dates and source statements are invented. Every input includes its source text. No source download, private packet or model call is required.

## What this can establish

An exact installed candidate is exposed to useful evidence opportunities, explicit gaps, declared child boundaries and a long-context limitation. Passing supports only this bounded operator workflow. Integrity-only success or rejecting everything cannot pass usefulness.

Use [EB #121's admission meaning](https://github.com/camerontjs-dot/evidence-bundler/pull/121): accepted is materially on-target and locally adequate for downstream semantic assessment. It is not support, refutation, truth, authority, applicability or completeness.

## Files and review order

- inputs/: eight standalone inputs in case order.
- OPERATOR-RUN.md and REVIEWER-GUIDE.md: initial cold operator/reviewer aperture.
- EVALUATION-GUIDE.md and EXPECTED-OPPORTUNITIES.json: frozen expectations, opened after initial review is recorded.
- MANIFEST.json: raw input-file, logical handoff, target and inline-source identities.
- DESIGN.json: classification, design time, case plan and exposure boundary.
- SHA256SUMS and FREEZE.json: pre-output integrity closure.

A supervisor can verify all hashes before handing only the initial aperture to a cold operator. Separate files do not establish reviewer independence. Record identity and actual exposure.

The released A2 validator is validators/contract_a_rc2.py, blob 42e5f5b3bf38d677445e9d01ea130ba604e53409, at Apparatus Contracts commit 529c92b49a34d5c610618551a8737f019f9fa332. The historical contract-a-wire-candidate-rc2 token is the released wire token.

## Freeze and corrections

No EB output on these inputs was observed before freeze. FREEZE.json records timestamp and closure hash. Input and expectation bytes are immutable for a run. Corrections require a separately named revision with first failure/reason preserved.

Outputs belong in a fresh directory outside this kit. Exact EB package/commit, environment, commands, decisions, output identities, time, manual steps and first failures belong in the execution receipt.
