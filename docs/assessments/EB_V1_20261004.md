# Evidence Bundler purpose and fitness assessment — 2026-10-04

## Decision

**EB should prepare useful, reviewable evidence from declared claims and bounded sources, preserve the path from source to admission, and make gaps visible for downstream assessment.** The first stable product should support the operator-reviewed Contract A 2.0 text/Markdown workflow described in [the purpose and interface contract](../EB_PURPOSE_AND_V1_CONTRACT.md).

EB already performs substantial parts of that job correctly. The evidence does not yet justify a dependable general-purpose `1.0.0` claim. Mechanical provenance and compatible output are necessary, but they do not establish that the retained material is useful or that an ordinary operator can complete the workflow with reasonable effort. [Issue #132](https://github.com/camerontjs-dot/evidence-bundler/issues/132) owns the current plan and subsequent decisions.

## Product scope

Keep the first v1 focused on operator-supplied A2 claims/declarations and bounded plain text/Markdown sources, deterministic evidence preparation, explicit reviewed admission, verifiable native/B output, and honest gaps. The frozen 10/3 policy is a known-imperfect integration baseline, not an established optimum. Its useful-yield and review-burden limits must be measured on the chosen workload before treating it as an acceptable stable default.

Automatic root/child/subject authoring is not necessary to consume legitimate upstream declarations. [#130](https://github.com/camerontjs-dot/evidence-bundler/pull/130) remains an optional prerequisite in [#124](https://github.com/camerontjs-dot/evidence-bundler/pull/124)'s separate prospective retrieval research route. Neither its green CI nor a later successful profile-writing attempt would demonstrate useful retrieval. Preserve those protocols, budgets, negative results and scope.

The B carrier still says `integration_candidate_only`; stable compatibility treatment needs an explicit decision. The Linux resolver also exposed substantial legacy ML dependencies for a lexical V1 workflow. A smaller installation surface is a sensible follow-up to measured installation burden, rather than evidence that retrieval quality improved. Document which interfaces and dependencies the first release supports.

## New acceptance work

The [eight-packet synthetic kit](../../research/eb_v1_workflow_acceptance_20261004) was authored and frozen before EB execution. The exact canonical A2 validator accepts all eight unchanged. It supplies five named adequate-evidence opportunities, four named gap obligations, a complete and incomplete `all_of` parent, and a separated-context limitation observation. One adequate opportunity is contrary to the claim's number; support-only admission must not pass.

The helper prepares actual installed-CLI output, gives a reviewer the retained text and exact claim/source/span identities, requires explicit review reasons and target notes, freezes reviews, replays only against the unchanged snapshot, and evaluates the named opportunities. Its fabricated always-reject and always-accept controls both fail. These are apparatus checks, not extra product or reviewer executions.

The first installed run and fresh-agent review **passed the frozen synthetic acceptance gate**. The reviewer received the guides and actual retained packets without the oracle, previous results or product code, saved each first judgment, and did not revise decisions after evaluation. The helper froze those records, replayed their admission decisions and confirmed that no native field except admission and the dependent package hash changed. The [review observation](../../research/eb_v1_assessment_20261004/workflow/REVIEW-OBSERVATION.md), [exact decisions](../../research/eb_v1_assessment_20261004/workflow/reviews) and [evaluation](../../research/eb_v1_assessment_20261004/workflow/EVALUATION.json) preserve the outcome.

| Case | Observed result |
|---|---|
| p01 — labeled effective date | One locally adequate relationship accepted. |
| p02 — contributing versus invited sites | Contrary numerical evidence accepted; disagreement was not treated as an admission failure. |
| p03 — complete `all_of` | One adequate relationship for each child; both wrong-child relationships rejected. |
| p04 — wrong subject | No accepted relationship; the target-specific gap preserved. |
| p05 — missing units/qualifiers | Fragment rejected; timing relationship remains a gap. |
| p06 — incomplete `all_of` | Signed-log child admitted; archive-retention child remains uncovered. |
| p07 — separated context | Header and table admitted together using their explicit same-note reference; unrelated custody text rejected. This case has no fixed admission-count gate. |
| p08 — empty source set | No decision rows manufactured; the target gap remains. |

Across eight packets and ten targets there were **13 retained relationships: seven accepted, six rejected, zero unresolved**. All five mandatory adequate targets and all four mandatory gap obligations passed; the complete/incomplete parent boundary passed. The helper's fabricated always-reject and always-accept alternatives both fail the frozen gate. All eight reviewed outputs also pass the actual canonical B1.2 verifier and pinned CAL intake, with exact equality between native accepted/retained pairs and CAL admitted pairs. The [consumer receipt](../../research/eb_v1_assessment_20261004/workflow/CONSUMERS.json) is bound to [verified local installed artifacts](../../research/eb_v1_assessment_20261004/workflow/INSTALLED-IDENTITY.json); the checker does not substitute package version strings for commit identity.

The material usability observations were manual JSON matching/entry, repeated passage identities needing child-specific decisions, and incomplete explanation of an empty packet's cause. Only p07 required inspecting the underlying source. Its table omits the subject and unit when detached from its retained header; the review accepted the explicit visible cross-reference, not the isolated tail passage. A supported review/display workflow must preserve that context or expose its limitation clearly. This is evidence for a presentation decision, not proof that every separated-context case is solved.

The reviewer recorded **306 seconds** across case intervals, including **112 seconds for p07**. These are measured agent/tool intervals with one-second resolution, ending before each save, not human throughput or complete installation-to-handoff time. The result establishes one bounded engineering observation. A fresh human or owner-machine review and the first real workload remain distinct evidence.

The first preparation attempt stopped before invoking EB because the helper mistook a directory marker for an active checkout. Its [failure record](../../research/eb_v1_assessment_20261004/APPARATUS-FIRST-FAILURE.json) is preserved. The helper was corrected to ask Git whether the run directory is inside a worktree, with a regression control; the frozen kit was unchanged and the next preparation was the first product exposure.

This engineered kit cannot estimate population recall or replace the frozen #121/#123/#124 studies. The next usefulness decision needs a named first real workload, prospectively chosen packets and adequate witnesses, permissible operator actions, and pre-outcome thresholds for adequate-target yield, complete-parent coverage, mistaken admissions, uncertainty and review burden. An empty but well-formed bundle is not a general usefulness pass.
